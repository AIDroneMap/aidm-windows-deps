Evidence: `test_header_debug_folder_is_release_payload` and `test_debug_verdict_lists_every_offending_path` in `tests/test_check_release.py` reproduce and cover the false positive from [dispatch run 42371745151](https://github.com/AIDroneMap/aidm-windows-deps/actions/runs/42371745151).
- Added the complete release check before artifact upload and a tag-only draft release job. Release builds of vcpkg ports install PDB files beside their DLLs. Packaging logs and removes those files before archiving. The checker accepts the asset set without a VC++ runtime zip, replaces SQLite only in its temporary Python folder, verifies shared SQLite operation, and rejects debug payloads and a mismatched port list. Added instructions for checking a downloaded release. Evidence: `tests/test_package_export.py`, `tests/test_check_release.py` and `tests/test_release_publish.py` cover packaging, verdicts and the draft command; the `release.yml` dispatch run is linked in the pull request for [issue #8](https://github.com/AIDroneMap/aidm-windows-deps/issues/8). The draft release itself waits for the maintainer's tag.

- A consumer of the deps export and the embeddable package uses the export's `sqlite3.dll` in place of the embedded copy, because the embedded SQLite lacks `sqlite3_column_origin_name` and `sqlite3_column_table_name`, which `gdal.dll` imports. The wheel probe applies this layout only to its temporary Python copy, prints and compares Python's and GDAL's SQLite versions, and checks a stdlib SQLite query. Evidence: `ProbeLayoutTests` and `SqliteProbeTests` in `.github/release/tests/test_gdal_wheel.py`, and the dispatch run linked in the pull request for [issue #6](https://github.com/AIDroneMap/aidm-windows-deps/issues/6).
- Added the GDAL 3.8.4 Python wheel, built against the GDAL in the same run's export with NumPy 2.3.2 and hash-pinned build tools. A temporary copy of the Python 3.12.10 embeddable package receives only the development headers and import libraries from the pinned Python 3.12.10 NuGet package. Its SHA-256 pin was computed after verifying NuGet's published SHA-512. The re-hosted Python archive stays unchanged. The wheel carries the export's GDAL licence notice, and the release lists include its licence and hash. Evidence: `.github/release/tests/test_gdal_wheel.py` covers required bindings, the array extension, rejected DLL and data payloads, and development-file selection; `release.yml` builds the wheel and prints version 3.8.4 after importing and reading an array in a fresh embeddable Python, with the dispatch run linked in the pull request for [issue #6](https://github.com/AIDroneMap/aidm-windows-deps/issues/6).

Evidence: `.github/release/tests/test_assets.py` covers publisher hash rejection, unchanged downloads, transitive port licences, nested notices and complete checksums; the dispatch runs are linked in the pull request for [issue #7](https://github.com/AIDroneMap/aidm-windows-deps/issues/7).
- Added the first manifest and export workflow at vcpkg baseline `6ecbbbdf31cba47aafa7cf6189b1e73e10ac61f8`, with one override per direct port and GDAL 3.8.4 with its default features. The export keeps the release copies of `libgcc_s_seh-1.dll`, `libgfortran-5.dll`, `libquadmath-0.dll` and `libwinpthread-1.dll` under `bin/`, which reference LAPACK needs at run time. Evidence: `release.yml` checks the zip's port versions and rejects debug payloads, with fixture coverage in `tests/test_export_workflow.py` and `tests/test_package_export.py`; its dispatch run is linked in the pull request for [issue #5](https://github.com/AIDroneMap/aidm-windows-deps/issues/5).
